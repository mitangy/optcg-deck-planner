| Option | Verdict |

## Goal

Ship a **staging** Expo-web build of `mobile/` on **Vercel** that talks to the **staging Colyseus** game server over **WSS**, so two people can open a URL, authenticate (or use Step 4 staging auth), queue/join, and finish a duel without Expo Go or a LAN IP.

Success looks like: CI (or documented one-command) produces a static web export; Vercel serves it; Chrome desktop + Mobile Safari can complete a ranked (or casual) duel against staging.

## Changes required (inventory)

### A. Client (`mobile/`)

| Change | Notes |
|--------|-------|
| Export script | e.g. `"export:web": "expo export --platform web"`; output `mobile/dist` (or Expo default `dist`) |
| Build-time env | `EXPO_PUBLIC_GAME_SERVER_URL=https://<staging-game-host>` (SDK derives WSS). Optional `EXPO_PUBLIC_API_URL` for FastAPI token mint once Step 4 wires it |
| Platform storage | Confirm join/auth persistence works on web (`localStorage` / cookies) — avoid SecureStore-only paths without web fallback |
| Deep links | Expo Router static hosting: correct `scheme` / asset paths; if ever subpath-hosted, set `baseUrl` — **prefer apex subdomain** to avoid subpath pain |
| Bundle hygiene | Atlas JSON in export; no Node-only imports; `react-native-web` already present |
| Smoke test | Playwright/Puppeteer against preview URL: load → create/join or queue → see board chrome |

### B. Game server (`game-server/`)

| Change | Notes |
|--------|-------|
| CORS / origin allowlist | Today no explicit CORS for browser clients; browsers need `Access-Control-Allow-Origin` for HTTP handshake + WS upgrade from the Vercel origin |
| TLS / WSS | Staging must be `https://` / `wss://` — browsers block mixed content from HTTPS Vercel pages |
| Auth validation | Step 4 game tokens accepted from browser `Authorization` / Colyseus join options (already planned) |
| Health | Keep `/health` for uptime checks |

**Do not** run Colyseus on Vercel serverless — sticky WebSockets + long-lived rooms need a persistent Node host (Render, Fly, ECS, etc.).

### C. Meta API (`backend/`) — if Step 4 tokens are live

| Change | Notes |
|--------|-------|
| CORS | Allow duel web origin for token mint / rating reads |
| Cookie vs bearer | Prefer bearer for game path (Step 4 already flags Safari cookie pain) |

## Test plan

| Case | Expect |
|------|--------|
| Local | `npm run web` still works against local game-server |
| Export | `expo export -p web` produces static assets without RN-web errors |
| Staging Chrome | Create/queue → board → `match_over` |
| Staging Mobile Safari | Same; reconnect banner if Step 4 shipped |
| Planner regression | Existing deck-planner Vercel project still builds from root `vercel.json` |
| Mixed content | HTTPS page + `http://` game server must fail closed (document; fix with WSS) |

## Risks

| Risk | Mitigation |
|------|------------|
| Subpath deploy breaks Expo Router assets | Prefer subdomain; if subpath, set `baseUrl` and test deeply |
| CORS too open | Explicit allowlist; no `*` with credentials |
| Preview deploys hammer staging | Shared secret / rate limits; optional preview → mock |
| Atlas / Bandai hotlink failures | Same private-prototype policy; CDN later (Step 5) |
