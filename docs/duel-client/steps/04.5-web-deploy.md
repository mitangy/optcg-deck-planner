## Why a separate frontend (not Expo export / not planner)

| Option | Verdict |
|--------|---------|
| Expo `export --platform web` as the product UI | Rejected for **product** web — fine for local smoke; weak desktop UX, Metro/Vercel friction, and the team wants an explicit **web frontend** |
| Add duel routes to `frontend/` (deck planner) | Rejected — different product surface, different release cadence; planner SPA must stay shippable independently |
| **New `duel-web/` Vite SPA** | **Chosen** — same Vercel/Vite ops as planner; browser-first layout path; shares protocol/atlas with Expo; Colyseus still authoritative |

Step placement (unchanged): 4 = browser-capable auth; **4.5 = frontend + staging URL**; 5 = production polish.

---

## Goal

Ship a **staging** duel **web frontend** (`duel-web/`) on **Vercel** that talks to **staging Colyseus** over **WSS**, so two people can open a URL, authenticate (Step 4 tokens), queue/join, and finish a duel in the browser — without Expo Go or a LAN IP.

Success looks like: `duel-web` builds with Vite; Vercel serves HTTPS; Chrome + Mobile Safari complete a ranked (or casual) duel against staging; deck-planner Vercel project untouched.
