What shadcn adds

shadcn/ui is a set of ready-made components (built on Radix and Tailwind) that get copied into the app. Both shadcn skins above come from the same code: the only difference is a block of about 60 colour and font settings.

What came for free

  • Menus, pop-ups and drawers just worked. Dropdowns, the market price pop-up, the phone menu, the phone battle log drawer, card previews on hover and scroll areas all looked right first time, with keyboard and focus handled.
  • Re-theming is one block. Swapping shadcn's grey theme for our parchment, sea and gold took one set of colour variables, with no per-component changes.
  • Charts come with it. The planner's cost curve uses shadcn's chart, and it picks up the theme colours on its own.

What fought back

  • Nothing for the board. Card slots, rested cards, the fanned hand, DON!! rows and card sizing are all custom either way, so the shadcn board looks almost the same as the Tailwind one.
  • Sized for business apps. Badges, tabs and cards came too tall and too padded for power labels and the phase strip, and had to be overridden.
  • Missing pieces. No stepper for owned counts, no segmented bar for counters, and its toggle buttons allow "nothing selected", which List/Grid can't have.
  • Some colours collide in our theme. A few of shadcn's surface colours end up the same navy in our palette, so selected items vanished until fixed one by one.

Stock vs our colours

  • Stock shadcn looks generic. Clean and readable, but black and grey everywhere: black top bar, white End turn button, grey chart bars that are hard to tell apart.
  • With our colours it reads as our app. Fraunces headings, parchment, sea and gold carry most of the identity, on both apps.
  • It adds Radix. shadcn pulls in Radix for behaviour, next to the Headless UI we already use, so we'd want to pick one.

What gets better

  • One set of colours for both apps. The palette lives in one Tailwind theme block, so both apps pull from the same list.
  • Phone layouts are quicker to write. Phone, desktop and landscape sizes go on the element itself, so there's no separate media-query file to keep in sync.
  • Pop-ups and menus get easier. Headless UI comes from the same team as Tailwind, so open, focused and selected states style in one word each, and menus float over the page without pushing anything.
  • Spacing and corners stay consistent. Everything snaps to one spacing scale, which is where most of the cleaner look on the right comes from.

What it costs

  • It isn't less code. The five prototype screens took about 1,300 lines of components, and the styling moves into long class lists inside the components.
  • The board is the hard part. Crew themes, light mode, the tilted board, text size and pop-up size settings all have to stay as CSS variables underneath, so it can't go all-Tailwind.
  • The tests would need rework. About 860 test lines find things by class names like .board-root and .float-card, and those names go away. Every visual snapshot would need re-blessing too.
  • Some layouts read worse. The board's grid placement turns into lookup tables, and a few layouts needed the same markup written twice for different sizes.

Same either way

  • The look is still ours. Tailwind is a way of writing styles, not a theme. Most of the polish on the right could also come from tidying our current CSS.
  • Headless UI stays. The shared pop-ups and menus in @optcg/ui keep their behaviour; only the styling would change.
  • Card art and data don't change. These shots use real catalog cards and a real OP17 tournament deck.

If we go ahead

Do it one screen at a time, planner first. Tailwind can run next to the current CSS, with its colours read from our existing variables, so each screen can switch over in its own PR with its own snapshot update. The duel board would go last, or keep its own CSS for good.

A cheaper middle path: keep plain CSS, but borrow the parts that made the prototype look cleaner, mainly one spacing scale, one set of buttons and chips, and shared colour tokens across both apps.
