# `@optcg/deck-analytics` — deck stats, draw odds and build hints

Shared by the deck planner (`frontend/`) and the duel app (`duel-web/`).

| Path | What |
|------|------|
| `src/deckStats.ts`, `src/drawOdds.ts`, `src/deckHints.ts` | Pure logic (no React, no network). Import from `@optcg/deck-analytics`. |
| `src/ui/` | React panels: `DeckStatsPanel`, `DeckHintsTray` + `useDeckHints`, `DrawOdds`, `SearcherOdds`, `useStatsAtlas`. Import from `@optcg/deck-analytics/ui`. |
| `src/ui/deckAnalytics.css` | Panel styles. They read the host app's colour tokens (listed at the top of the file). |
| `deckStats.json` | Per-card atlas, generated by `npm run export-planner-stats -w @optcg/rules`. Each app's build emits it as a hashed asset and fetches it on first use. |

Apps compile the sources directly: each app's `vite.config.ts` aliases `@optcg/deck-analytics` to `../packages/deck-analytics/src` and dedupes React, and its `tsconfig.json` maps the same paths (plus `react` to the app's own types, since this folder has no `node_modules`).

Tests: `npm run test:deck-analytics` from the repo root. Mutation proofs: `node tools/mutation-check/run.cjs deck-analytics`.
